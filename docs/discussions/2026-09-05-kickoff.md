## 项目方输入

项目方希望建设一个 AI 视频平台：用户输入资料后，系统生成素材、脚本和其他内容，最终产出可发布到抖音和其他平台的视频。首个垂直方向为摩托车，希望利用 3D 获得炫酷、合理且好看的视觉效果，最终具备 Blender 影视级车辆建模、材质与渲染全流程能力。

项目方要求先探索合理架构，并研究 GitHub 高热度公开项目的商业模式、架构风格、设计思路、UI 风格和功能。在流程充分讨论并达成一致后，再建立 Spec、执行计划并据此开发和测试。讨论、研究、建议和项目规划均需持续沉淀到仓库文档。

提供的参考制作清单覆盖指导网格、车身面板、玻璃塑料、后视镜、格栅、牌照区、灯组、雨刷、车轮、车门、仪表板、方向盘、中控、前后排座椅、安全带、脚垫与踏板，并包含基础/复杂材质、山景多角度、车内视角、日落与街景渲染。

## 本轮识别的歧义

参考清单是汽车课程结构，而首期产品方向是摩托车。车门、前后排座椅、方向盘、雨刷和车内视角不能直接进入摩托车需求。本轮已将其解释为“按部件制作、材质分类、多个场景与角度输出”的方法参考，并在项目简报中给出摩托车组件映射。

“Blender 影视级车辆建模渲染全流程”也存在两种含义：平台每次替用户从零建模，或平台内部具备生产精品资产并自动复用渲染的能力。基于现有技术成熟度，本轮建议第二种，并记录为待确认 ADR。

## 本轮形成的建议

- 产品主链路采用精品 3D 资产、受控镜头模板和 AI 内容生成。
- 用 Storyboard 把脚本、车辆动作、镜头和音频绑定到每个 Shot。
- 最终渲染前提供低成本预览和人工确认。
- Blender MCP 用于资产师辅助，不直接进入租户生产执行链路。
- Hunyuan3D/TRELLIS 等用于实验和辅助资产，不承担首期主车型最终质量。
- 正式 Spec 在目标用户、输入、车型真实性、时延与成本确认后建立。

## 下一轮议题

优先确认目标付费用户、首个使用场景、用户可提供的输入、是否必须还原真实车型，以及单条视频可接受的等待时间和成本。
