# 2026-09-05 首期定位讨论

- 状态：已记录
- 参与方：项目方、Codex

## 已确认信息

- 首期暂不做付费功能。
- 用户是普通自媒体创作者，核心使用场景是账号日更。
- 用户可以提交文字、照片、多角度图片和视频，但大多数情况下只提供创意思路、文字和描述。
- 平台负责生成脚本等内容并先交给用户确认，确认后再继续生成对应素材和成片。
- 默认生成真实车型；仅当用户有强烈、明确意愿时生成不存在的概念车型。
- 项目后续需要扩展母婴、育儿等其他视频类型。
- 当前尚不知道如何评估生成成本。

## 影响与解释

真实车型和低输入量同时成立时，平台必须维护受控的真实车型资产目录。用户输入车型名称后，先匹配品牌、车型、年款和配置，再让用户核对。目录外车型不能通过纯文字生成后冒充真实车型。

“用户确认”应成为持久化工作流中的正式审批节点。脚本/分镜版本一旦确认，最终渲染引用不可变版本；后续修改生成新版本，避免画面、旁白和成本记录无法对应。

暂不收费不等于暂不计量。为了控制免费日更工具的资源消耗，系统需要从第一版记录逐镜头 GPU、API、存储、重试和合成成本，并在 P0 后决定每日额度。

扩展母婴/育儿意味着 Blender 只是摩托车内容包的执行器之一。通用平台应围绕项目、脚本、Storyboard、镜头、审批和成片构建，领域输入、资产、生成方式与审核规则由垂直内容包提供。

## 新增风险

- 只有文字输入时，真实车型的年款和部件准确性无法稳定保证。
- 日更频率可能与高质量 Cycles 渲染时间冲突，需要低成本预览、队列和模板复用。
- 母婴/育儿可能包含医疗、营养和儿童安全建议，需要可信来源、内容边界和人工审核策略。
- 免费开放规模未确定，无法计算需要多少 GPU 和全站每日预算。

## 下一轮优先项

确认首批 POC 车型、日更内容主题、目标视频规格、免费测试人数和每人每日生成量。
