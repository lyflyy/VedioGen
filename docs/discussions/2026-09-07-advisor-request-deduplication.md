# 创意建议请求去重与失败恢复

日期：2026-09-07。延续用户“只有文字，由平台准备素材”的输入边界。本轮解决真实 Blender 工程流程中已经发现的创意建议重复调用，不新增车型校准片，不代表两款车的正式视频验收。

## 问题与选择

此前 `POST /projects/{id}/advisor-runs` 每次直接调用模型，成功后才写入建议记录。页面在等待 GPT 时刷新，新的前端实例看不到任何已完成记录，再次提交就会重复消耗模型用量。前端 `useRef` 无法跨页面解决这个问题。

继续使用现有同步 API 和单进程内部 MVP 部署，不引入新的工作流框架。采用 Python 标准库 `concurrent.futures.Future`、短临界区锁、SQLAlchemy 持久化输入指纹，实现同项目请求合并；不是自建分布式任务平台。

## 当前契约

- 同项目、同输入的并发请求等待同一个 Future，收到相同的建议 ID 或失败响应。模型网络 I/O 期间不持有全局锁或数据库写锁。
- 最新成功建议记录保存 SHA-256 输入指纹，后续相同输入的显式 POST 复用该记录，不再次调用模型。指纹包括项目输入、事实、素材、执行能力上下文和已发布路由版本；不按标题简单缓存，不保存额外明文凭据。
- 新增要求、素材变化、标题变化或发布新路由后允许生成新建议。历史记录指纹为空时不推测它属于当前输入。
- 生成期间同项目的新输入请求返回 409，不把旧输入的进行中结果当成新要求的结果。旧请求完成后重新核对输入；不一致则保留其已产生的结果和调用记录，但不设置为当前建议，并返回 409。
- 模型失败由并发请求共享，不写成成功建议。用户可以显式重试；不把失败永远缓存。
- 首次建议失败后页面显示“创意建议未完成”和重试按钮，不继续假装生成中。点击重试不插入空用户消息；仅重新载入工作区数据不会自动重试模型。
- 现有数据库只增加可空 `advisor_runs.input_fingerprint` 列，旧结果保留。

代码：`services/api/src/vediogen_api/advisor.py`、`creator.py`、`models.py`、`database.py`；界面使用既有 `project-workspace.tsx` 状态与按钮。

## 明确限制

- 进行中的去重是单 API 进程内能力，不支持多个 Uvicorn worker / 多副本，也不能保证进程被杀后供应商已收到的请求不会再次计费。未来需要持久化任务领取和供应商请求查询时另做升级。
- 接口仍等待模型完成后返回，沿用 202 响应码，不是立即入队返回的异步咨询任务；已同步更新 OpenAPI 描述。网络断开后的工作区可能暂时没有建议，但新请求能加入同一进行中调用。
- 不能由此推断跨所有模型操作的 exactly-once；脚本生成、素材规划与提供商 fallback 不属于这次去重范围。
- 输入指纹不是完整版本治理或模型配置审计；部署的原地修改没有全部纳入指纹，变更模型路线应发布新的路由版本。系统提示词/契约更新时需更新指纹中的 `contractVersion`。
- 用户刷新失败页面仍可能再次发起请求，这属于重新进入流程；本轮不增加持久化失败任务与恢复 UI。
