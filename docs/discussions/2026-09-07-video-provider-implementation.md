# 视频 Provider 实现与长期目标检查点

> 后续方向调整：用户要求优先 Codex/GPT 与本地软件，减少付费视频供应商依赖。[本地优先计划](../plans/2026-09-07-local-first-media.md) 优先于本文的“先取得云视频权限”执行顺序。本文保留已完成实现的事实，云 API 改为可选。

## 当前目标

继续执行已建立的长期 Goal：企业内部 MVP 从 GPT 咨询、脚本确认，到真实视频镜头、局部重做、合成下载；最终让张雪 800X 与春风 800MT 两条样片获得用户至少 80 分验收。Goal 保持 active，不以隔离测试代替画质验收。

## 本轮落地

- 核实 fal 官方队列文档和 Kling OpenAPI，新增可选 `fal-video` 适配器。
- 新增视频执行管理页，复用平台、部署与加密凭据，默认停用。
- 参考图、提示词和 5/10 秒镜头进入后台，返回视频实际下载后交给 FFmpeg 合成。
- 保存供应商任务 ID，恢复查询；主动重做重新计入估算预算；提交不明时禁止盲目重提。
- GPT 分镜描述、运镜和连续性规则组成视频提示词初稿，用户可编辑。
- 不发起付费调用，不填写虚构账单，不把模拟供应商响应当成真实模型验证。

详细字段与限制见 [图生视频增量契约](../specs/internal-video-execution.md)。

## 仍需确认

1. 是否采用 fal，或提供中转站的视频 API 文档与确实开通的权限；文本兼容不代表支持视频队列。
2. 视频凭据填在后台，不在讨论记录或 Git 中保存明文。
3. 真实试验总额度；依据实际价格填参考单价与单任务预算，账户侧另设额度。
4. 两款车已确认参考图片、目标风格参考，以及是否接受单图视觉环绕。
5. 两条片按脚本20、主体25、画质20、运动20、声音字幕15评分；主体和运动至少4/5，不能错车型或漏必需镜头。

## 下一能力顺序

先从已确认参考图做真实单镜头，再做环绕和骑手对照，合格后补完整第一条。失败优先调整参考图、Prompt 和模型。第一条通过后补轻量车型参考池，让纯文字也能选择已确认车型；再按实际缺陷补配音、环境音与节奏模板。
