# 模型配置界面增量

## 用户诉求

已有模型与平台信息能够修改；能够新增模型，选择平台，录入 API Key 和请求地址。配置通过界面完成，而不是依赖代码修改。

## 本轮实现

- 保留平台、Key、模型、能力路由分层，补齐三个配置页的编辑入口与保存接口。
- 模型切换平台后，凭据列表只提供所选平台的有效 Key；模型页显示继承的请求基址并提供平台/Key/路由入口。
- 编辑 Key 不显示已有秘密；留空不替换，实际换 Key 需要确认，保存后清空输入。
- 连接变更后模型需重新探测；更名不影响就绪状态；已有部署 ID 与路由引用保持不变。
- 请求参数错误转为可读表单反馈；重复提交同一 Key 不绕过 429 冷却。
- 根据 `frontend-design` 和 `vercel-react-best-practices` 的指引复用现有 UI。截图复核发现旧表单输入样式缺失，已为这三个配置表单补齐双列/单列布局、输入尺寸及集中操作区。

## 验证记录

- API 全量：242 项通过；含 13 项新增配置测试。现有测试库有 2 条弃用警告，不影响执行。
- 浏览器：管理端新增/路由链路与模型编辑链路两项通过；覆盖刷新后参数保留、Key 不出现在正文与浏览器存储、重新探测就绪。
- 编辑链路通过桌面和 390px 手机视口的截图、横向溢出与严重可访问性问题检查。
- TypeScript 与 ESLint 检查通过。
- 探测与网关参数传递测试使用 mock；浏览器使用隔离 Fake 平台。本轮没有消耗真实模型额度，也没有改动用户真实平台、Key 或模型配置。

检阅服务继续使用 Web `http://127.0.0.1:3001`、API `http://127.0.0.1:8001`。更新 API 前核查生成、咨询、调用、素材发现表，没有活动任务。

API 更新后在 3001 对真实已有平台、Key、模型分别打开编辑表单，只读确认字段回显，未点击保存或探测。1440px 桌面和 390px 手机截图位于 `.data/internal-mvp/model-configuration/`；三个页面均无横向溢出，Key 输入框为空。

## 未扩大范围

本轮没有新增生成供应商协议、自动发现模型能力、模型计费或复杂版本审批。既有中转站 429 是否恢复未重新验证；配置功能通过不代表上游限流已解除。视频生成质量与模型供应能力仍按原路线单独验收。

对应执行契约：[模型配置与编辑](../specs/model-configuration-editing.md)。
