# 纯文字输入与本地生成入口

- 日期：2026-09-07。
- 用户明确补充：目前只有文本描述，没有可提供的照片或 3D 模型。
- 用户主流程不以自行准备模型、照片或视频为前置条件。平台负责寻找或生成素材；用户负责表达意图、确认候选与评审输出。
- 本条优先于此前要求项目方先提供参考图片/3D 文件的近期执行顺序。

## 当前代码证据

1. 创建项目接受 `initialMessage`，GPT 创意咨询和分镜入口已存在。
2. `creator.py` 创建项目时调用 `fixtures.build_project_facts`。该函数对包含 800MT 的文本直接写入“春风 800MT”，其他情况直接用项目标题充当车型，并标记 confirmed。这不是经过 GPT 提取、联网核验或用户独立确认的车型识别能力。
3. `generation.build_plan` 当前依赖绑定已上传素材；图生视频仍要求参考图。不存在从纯文字自动获得真实车型素材的完整链路。
4. Blender / 本地模型路径尚未安装和接通；不能把规划文档作为已实现证据。

因此，在单独测试 Blender 渲染器之外，下一核心产品能力应是“文字到素材准备”。只有测试模型渲染通了而素材仍完全依赖用户提供，不能完成本项目的主要输入场景。

## 用户流程

```text
文字描述
  -> GPT 提取车型、风格、必需镜头与顺序
  -> 自动查找车型资料与参考图片/可用 3D 资产
  -> 展示匹配候选、名称与图片，必要时问一个消歧问题
  -> 用户确认主体，不要求用户自行制作文件
  -> 按资产条件选择本地渲染/本地生成工作流
  -> 关键镜头先预览，确认方向后完成其他镜头
  -> 合成、局部重做、下载与人工评分
```

## 三类素材结果

| 情况 | 平台处理 |
| --- | --- |
| 找到匹配的可用 3D 资产 | 校验资产、展示预览；确认后用 Blender 制作细节与环绕 |
| 只有匹配参考图片 | 优先本地参考图生成短镜头；明确环绕是生成效果，不承诺准确的完整三维结构 |
| 没有可靠匹配素材 | 展示检索缺口；可继续完善脚本，不静默换车型。概念车方向仅在用户明确接受后使用 |

用户对车型名称的表达应被保留，但不代表系统已经拥有该车型的准确几何。应区分用户指定名称、搜索候选、实际资产匹配三件事。禁止把“凯越 800X”等相似搜索结果擅自认作“张雪 800X”。

## 下一实现顺序

1. 修正自动 confirmed 的事实占位逻辑，使用结构化提取保存用户指定的主体与镜头要求；名称未解析清楚时不凭标题认定。
2. 接素材发现与准备任务：搜索候选、读取来源、匹配主体、参考图下载/展示。搜索失败需要可见状态，不填入仓库通用图片。
3. 提供轻量素材确认，不引入审批版本树；缓存已确认车型参考以支持日更复用。
4. 并行能力在后续实现中按资源顺序完成：Blender 本地执行器，以及适配本机 8GB 显存的单个本地 I2V 工作流。先做真实测试再决定选择，不一次接入大量软件。
5. 先验证指定车型细节、环绕和骑手结尾，再完成两条样片。仍需真实输出与用户评分，不以纯文字转分镜作为最终完成。

## 本轮边界

仅确认用户输入条件、检查代码差距并更新执行方向；没有安装软件、下载权重、调用付费模型或宣称自动素材生成已经实现。不会再次把提供照片/模型当作用户必须先完成的任务。
