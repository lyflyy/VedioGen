# 本地优先视频生产路线

- 日期：2026-09-07。
- 用户最新方向：尽量利用 Codex、GPT 与本地可安装软件，减少对付费视频供应商的依赖。
- 后续已确认输入条件：用户目前只有文字。平台承担素材发现/生成，不能要求用户先准备模型或照片；见 [纯文字入口补充](../discussions/2026-09-07-text-only-local-generation.md)。
- 决策：本地生成/渲染作为优先探索路线，付费视频 API 改为可选补充，不再作为下一步开发和试验的唯一前置条件。
- 本轮完成硬件检查、公开资料核验和规划；未安装软件、下载模型权重或执行生成性能测试。
- 原目标不变：平台闭环、两款指定车型、关键镜头齐全、用户认可至少 80 分。不以程序化通用摩托车或图片缩放替代真实车型视频。

后续实现更新：文字到参考图入口已实现；ComfyUI GPU 服务与平台适配已安装/接通。当前权威进展见 [本地推理实测增量](../discussions/2026-09-07-local-inference-evidence.md)，本计划中的“未实现”描述保留为制定时的基线。

## 1. 本机情况

| 项目 | 本轮检查结果 |
| --- | --- |
| GPU | NVIDIA GeForce RTX 4070 Laptop GPU |
| 显存 | nvidia-smi 报告 8188 MiB，约 8GB |
| 系统内存 | Win32_ComputerSystem 报告约 15.7 GiB |
| 可用磁盘 | C 约 49.3GB；D 约 227.3GB，动态值 |
| 已找到工具 | FFmpeg、ffprobe、Git、GitHub CLI、uv |
| 未找到工具 | PATH 与检查的常见目录未找到 Blender；PATH 未找到 Ollama。不能据此断言整机绝无安装 |

WMI 显卡 AdapterRAM 存在约 4GB 的上报值，显存判断采用 nvidia-smi，不采用该截断字段。

这不是高显存工作站，但也不必先购买云视频额度或更换显卡。优先测试受控 Blender 场景与低显存推理方案；不把能启动等同于能稳定日更、能达到 80 分。建议模型与缓存后续放在 D 盘的独立目录，实际安装前核对体积及工作目录，不默认占满 C 盘。

## 2. 角色分工

| 环节 | 优先方案 | 边界 |
| --- | --- | --- |
| 研发与工具自动化 | Codex 编写、运行、调试场景脚本与适配器，检查结果 | Codex 不替代本地视频模型、显卡或车型资产 |
| 创意咨询、文案与分镜 | 保留现有 GPT 调用，给建议并由用户确认 | GPT 云调用仍可能产生费用；不把现有订阅假定为任意 API 免费额度 |
| 车辆细节、灯光、真实模型环绕 | 本地 Blender：资产导入、相机模板、材质、EEVEE 预览及按需 Cycles | 有正确可用 3D 资产是前提；质量与速度需实测 |
| 图像与生成式运动 | 本地 ComfyUI 或 LightX2V + 选定权重 | 模型、量化与工作流需适配 8GB 显存；不是所有工作流都免费或本地 |
| 剪辑、字幕、音轨、转码 | 已接通的 FFmpeg / ffprobe | 继续使用真实片段，输出尺寸不冒充新增细节 |
| 复杂失败镜头 | 先调整资产和运动方案，再由用户选择是否用云供应商 | 不自动降级到付费 API，不偷偷删掉困难分镜 |

生产应用继续由平台后端执行受控工具与任务队列，不把当前交互式 Codex 会话当成一个未经验证的长期生产服务。GPT 负责高层计划，Blender/本地推理服务负责画面，FFmpeg 负责合成。

## 3. 已核验的公开项目

关注量为本轮 GitHub CLI 查询快照，不等同于质量评分或本机性能证明。

| 项目 | 关注量 | 采用判断 |
| --- | ---: | --- |
| [Blender 官方镜像](https://github.com/blender/blender) | 20,063 stars | 优先采用成熟渲染器与 Python API，不自写 3D 引擎 |
| [ComfyUI](https://github.com/Comfy-Org/ComfyUI) | 131,751 stars | 候选本地节点工作流与 API，不复制它的整套 UI 到平台 |
| [Wan2.1](https://github.com/Wan-Video/Wan2.1) | 16,939 stars | 候选权重体系；不能把 T2V-1.3B 的显存需求当成 I2V-14B 的需求 |
| [LightX2V](https://github.com/ModelTC/LightX2V) | 2,784 stars | 优先评估其低资源量化/offload 路线，避免自己实现推理优化 |

具体证据：

1. [Blender 命令行渲染文档](https://docs.blender.org/manual/en/latest/advanced/command_line/render.html) 确认可 `-b` 无界面运行，按帧或动画输出；参数顺序有要求。
2. ComfyUI README 明确支持 Windows、本地 API、JSON 工作流与离线运行；`--disable-api-nodes` 可禁用内置可选付费 API 节点。第三方节点需另查，不能因为安装了 ComfyUI 就认定工作流无云调用。
3. Wan2.1 README 对 T2V-1.3B 给出约 8.19GB 显存、RTX 4090 上约 4 分钟生成 5 秒 480P 的项目自报数据。该数据不是本机测试，不能换算承诺 RTX 4070 Laptop 的速度，也不代表参考图保真能力。
4. Wan2.2 README 的 TI2V-5B 示例要求至少 24GB 显存。不能直接将原始示例作为这台机器的默认路线。
5. [LightX2V 低资源指南](https://github.com/ModelTC/LightX2V/blob/main/docs/EN/source/deploy_guides/for_low_resource.md) 明确面向 8GB 显存 + 16/32GB 内存，最低 16GB、建议 32GB；说明量化及磁盘/CPU/GPU 分层 offload。可作为本机试验依据，尚未验证本机速度、Windows 依赖与画质。

本轮尝试访问 OpenAI 的 Codex CLI 与 noninteractive 官方页面均遇到 403，因此不提出新的 OpenAI 模型、定价或订阅权限结论。保留现有已经接入的 GPT，不因路线调整先迁移模型。

## 4. 两款车的镜头如何落地

| 镜头 | 本地优先路线 | 主要依赖 |
| --- | --- | --- |
| 张雪 800X 车辆细节 | Blender 特写模板 | 指定车型可辨识的几何与材质，不能用通用模型换标 |
| 张雪 800X 360° 环绕 | 正确 3D 模型上的完整相机轨道 | 单张照片看不到的背面不能自动认定为真实；需要模型或足够参考 |
| 张雪 800X 最后皮衣骑手驾驶 | 骑手绑定与车辆路径动画；本地 I2V 作备选试验 | 骑手动作、轮速、接地、衣物与车体关系；先保留结尾要求 |
| 春风 800MT 首镜环绕 | Blender 车型资产 + 环绕模板 | 车型主体准确 |
| 沙漠扬尘、转速表 | 简化场景与受控粒子/材质动画，仪表独立特写 | 原车仪表参考、扬尘遮挡与接地 |
| 涉水与抬头 | 路径/车辆姿态动画，加受控水面效果 | 运动可信度与水体模拟成本较高；不承诺一次自动成功 |
| 山林无人机远拉 | 受控场景、散布植被和相机路径 | 场景规模、显存、主体不能在拉远中消失或改变 |

并非每个镜头都必须使用视频扩散模型。对车辆保真和可重复环绕，3D 通常更可控；驾驶、涉水仍需要动画/素材和人工打磨。模型与场景首次搭建有成本，复用后同车不同脚本才有明显收益。

## 5. 架构调整建议

保留现有 Creator/Admin、GPT、分镜、后台任务、片段重做、合成下载。新增本地执行器，不推翻已运行的平台：

```text
用户输入 -> GPT 讨论和分镜 -> 用户确认
                         -> Blender 本地渲染
                         -> 本地生成工作流（待选定）
                         -> 上传视频
                         -> 可选云视频（默认关闭，独立确认）
                      -> 实际片段 -> FFmpeg -> 预览/下载/人工评分
```

- 近期先实现一种本地路径并真实验证，不同时接一大批模型。
- 后台配置需涵盖 Blender 可执行文件、素材库/输出目录、本地服务地址、工作流与权重检查、GPU 状态；这部分尚未实现。
- 沿用单媒体任务执行器，避免 Blender 与本地模型同时争用 8GB 显存。
- 本地失败明确提示原因，云端 fallback 默认为关闭；即使以后配置云端，也必须确认费用。
- 已实现 fal 适配器保留但不作为默认必选项。本轮未改变任何付费调用开关。
- 费用区分 GPT/云调用、耗时与本地资源；不显示“本地所以总成本为零”。

## 6. 下一步实验与退出标准

1. 先补文字到素材准备：由平台提取主体、搜索真实车型参考与可用 3D 资产、展示候选供用户确认。现成 `.blend/.glb/.fbx` 最有利，但不要求用户提供；搜不到则明确缺口，不承诺仅凭名称精确还原。
2. 安装独立 Blender 环境，先做简单测试场景验证后台渲染、实际输出、进度和取消；测试场景不得标为车型样片。
3. 导入已确认车型资产，渲染细节与环绕，检查几何、车标、构图、完整运动、显存和用时。
4. 另开本地视频 POC：按 LightX2V 低资源指南或经过验证的 ComfyUI 工作流，固定一张参考图和短片长度，测试一次真实推理。先核对模型体积，不盲目下载多个十几 GB 权重。
5. 用同一个骑手驾驶分镜比较本地 3D 与本地 I2V，记录生成时间、显存、错车型/变形、可用片段比例，再决定生产路径。
6. 关键镜头可用后，从平台完成第一条张雪 800X，再完成春风 800MT；两条按既定 80 分标准人工验收。

本轮不承诺本机单镜头生成时长，也不要求马上换硬件。本机实测若证明内存瓶颈，再考虑加内存；若实际业务频率超出本机能力，可选一台公司内网 GPU 机器运行同样的本地执行器，不必变成按条购买视频 API。
