# 长期路线图与近期行动

> 适用性更新：用户随后明确企业内部 MVP、优先 80 分视频。本文“先完整治理、后样片”的顺序已被[内部 MVP 计划](2026-09-06-internal-mvp-reset.md)取代；其余能力保留为长期候选，不是当前前置门。

- 状态：待确认
- 日期：2026-09-06
- 规划跨度：未来 6 至 12 个月，按滚动窗口维护，不是交付日期承诺。
- 当前事实：已有 Web/API、真实 GPT 创意与分镜调用；确认、契约、任务恢复和管理验证存在待修缺口；真实视频与 Blender 质量未验收。
- 范围：本轮只规划，不代表已经开始整改、采购、模型切换或真实付费测试。

## 1. 长期目标

建立面向普通自媒体创作者的 AI 视频工作平台：用户输入思路和可选素材，平台协助选题、判断和规划，用户确认后生成可编辑、可追溯的视频结果。先把摩托车日更做实，再验证母婴/育儿等内容方向。

长期积累的核心不是模型列表，而是：

- 用户可理解的创作和修改流程。
- 带明确来源、约束与版本的脚本和镜头数据。
- 可复用的主体资产、镜头模板和领域质量标准。
- 可恢复、可计量、供应商可替换的生产系统。
- 真实创作者使用反馈和稳定的质量评测集。

近期继续不做支付、套餐和充值。免费阶段通过受控名额、额度、复用和成本监测运行；是否商业化另行决策，不因规划到第 12 个月自动开始收费。

## 3. 分阶段目标

以下按确定开始执行后的相对时间估计。假设项目方每周可检阅、开发持续投入、所需 API 和素材及时可用；人员工时尚未确认，因此第一周期结束后必须重估。依赖延迟时顺延相应阶段，不用降低验收标准换日期。

| 规划窗口 | 对应批次 | 主要目标 | 可检阅结果与进入下一阶段的条件 |
| --- | --- | --- | --- |
| 第 1 至 2 周 | R0 首批切片 | 修已复现缺陷，建立隔离回归，验证持久 Advisor | 未确认/非法修改被拒绝；真实探测不虚报；Advisor 有持久 Run 和刷新恢复演示。这不是整个 R0 已完成 |
| 第 3 至 6 周 | R0 收尾 + R1，准备 R2 | 完成流程保障与创意顾问，选定单个视频 Provider | 完成 A/B 的发布门；两个用户样例准确形成可确认分镜；真实调用前配置预算与素材路径 |
| 第 7 至 12 周 | R2 + R3 | 先单镜头，再完整摩托车样片 | 真实输入、任务、逐镜头输出、合成和费用可追溯；用户验收两条样片；不把 MP4 下载成功等同车型保真 |
| 第 4 至 6 个月 | R4 的日更部分 | 小规模持续使用，减少返工和浪费 | 建议招募 5 至 10 位创作者，连续使用至少两周；记录接受率、耗时、失败、成本及停止使用原因，再决定扩大 |
| 第 7 至 12 个月 | R4 的领域扩展与按需扩容 | 第二内容包通过独立验收，形成稳定平台 | 摩托车核心无需重写即可支撑育儿演示；有真实需求再上线第二领域；按负载和运维数据扩容 |

这不是必须耗满一年的排期。验证更快可提前推进；样片质量、成本或稳定性不合格时，应缩小范围继续迭代，不能直接进入扩量阶段。

### 第一阶段：从“能调用”到“能可靠完成”

优先消除确认绕过、非法分镜、虚假检测、错误泄密和重复执行。使用隔离数据库、独占测试端口和显式 Fake，避免测试污染真实配置。建立版本迁移和持久任务后，前端显示任务状态，而非长时间等待一次同步 HTTP 响应。

不新增大量页面，不先做视频时间线编辑器。界面只补真实流程所需的输入状态、确认版本、错误、恢复、取消和重试反馈。

### 第二阶段：从“会写脚本”到“会协助决策”

将用户事实、素材观察、外部证据和硬约束分开保存。AI 顾问说明为什么推荐某种创意、缺什么素材、成本和保真有哪些取舍。用户两次确认仍是生产入口，不让模型替用户确认。

候选模型在固定案例中比较后按能力升级。先用同一模型承担多个阶段，只有证据表明另一部署更适合某任务时才分流；不为“多 Agent”而增加常驻 Agent。

### 第三阶段：从“单次样片”到“可重复生产”

首先生成一个真实 5 至 8 秒镜头并测量质量与费用，再扩展到完整分镜。加入逐镜头失败恢复、产物复用、字幕/音轨和机器质检。

每条成片记录实际使用的输入、确认版本、Provider 请求、输出和费用来源。把模型生成失败、素材不足、车型漂移、合成错误分开处理，不让用户遇到所有错误都只能重做整条视频。

### 第四阶段：验证日更价值

先服务小范围创作者，观察他们是否愿意重复使用，是否能在可接受时间和费用内得到足够多的可用成片。做选题历史、风格偏好、项目复用、系列模板和失败运营；反馈必须来自真实项目。

发布平台数据初期由用户手动提供；导出次数不能当作发布次数，发布次数不能当作播放效果。直发抖音需要独立接口与账号接入验证，未验证前保持下载交付。

### 第五阶段：验证平台性而非复制另一个项目

先选择一个边界清楚的育儿内容形态，例如日常用品整理或非医疗生活步骤演示。它复用核心状态机、运行和产物机制，仅替换输入、Prompt、镜头策略和质量规则。

医疗、营养及儿童安全建议的准确度不能由摩托车样片测试证明，未经独立质量验证不纳入首个演示包。母婴和育儿也不同时全面铺开。

## 4. 软件与资产两条工作线

| 工作线 | 最小交付 | 依赖 | 何时扩大 |
| --- | --- | --- | --- |
| 平台软件 | 顾问、确认、Run、Provider、逐镜头产物、合成和 QC | 开发、模型/API、数据库和存储 | 真实用户重复使用且稳定性/成本可接受 |
| 摩托车资产与 Blender | 一个已确认车型资产、基础材质、固定环绕模板、预览与最终渲染样片 | 真实多角度参考、可用 3D 资产、艺术制作能力和渲染环境 | 第一车型通过结构、材质、运镜与性能验收后再扩车型 |

不把“自动从一句话重建准确车型”作为平台上线前提，也不承诺一张照片能够生成准确的另一侧结构。生成视频、用户素材、Blender 独立标注来源与质量档。

高速驾驶、沙漠、涉水抬头与无人机远拉等复杂运动镜头单独验收；静态 360 度环绕通过不能证明动态骑行已经可用。

## 5. 每个阶段需要的资源

以下是职责，不代表必须招聘对应人数。人员可兼任，但编码助手不能替代项目方的样片接受与预算决策。

| 职责/资源 | 需要承担的工作 | 最迟需要到位 |
| --- | --- | --- |
| 项目方/产品负责人 | 范围取舍、费用上限、每周检阅、真实样片验收 | 立即；没有决策人无法冻结质量标准 |
| 工程开发与测试 | 全栈切片、迁移、适配器、故障测试、发布与文档 | R0 起；首周期记录投入后再做容量估算 |
| 模型与视频账号 | 候选模型权限、一个视频 API、试验额度 | 模型实测/R2 前；通过 Admin 配置 Key |
| 运行与存储环境 | Linux/容器 Worker、PostgreSQL、对象存储或 Provider 直传 | 持久任务 POC/R2 前分别验证 |
| 车型素材与 3D 能力 | 多角度参考、一个资产、材质和运动镜头验证 | Blender 分支开始前；可以外部合作或使用已有资产 |
| 测试创作者 | 真实输入、使用过程反馈、接受/拒绝原因 | R3 后的小范围试用 |
| 领域评审 | 第二领域事实与表达质量、易误导内容识别 | 第二内容包进入真实用户前 |

不预先采购 GPU 集群或训练模型。先比较单个视频 API 与固定 Blender 场景的每个合格镜头成本，再决定是否需要自托管算力。

## 6. 质量、成本和扩量决策

长期主指标建议为“每位活跃创作者每周接受的可交付成片数”，同时观察单条接受成片成本和从输入到接受的耗时。只提高生成次数而增加废片，不算进步。

| 指标 | 如何计算/观察 | 如何用于决策 |
| --- | --- | --- |
| 流程正确性 | 确认、权限、版本、幂等、生产禁用 Fake 的回归结果 | 关键不变量有失败就不发布，不用平均成功率掩盖 |
| 技术完成率 | 可执行且已经确认的 Run 中，有限重试内完成真实产物的比例；取消和输入阻断另列 | 先形成基线，再决定稳定性目标和扩大人数 |
| 内容接受率 | 用户接受的成片数 / 已交付候选成片数，记录拒绝原因 | 区分脚本、主体一致性、动作、节奏问题，决定投模型还是投资产 |
| 单条接受成本 | 全部相关咨询、生成、失败重试、复核、合成/存储费用 / 接受成片数 | 没有接受成片时报告未定义及总支出，不用除零或记零 |
| 创作效率 | 输入到确认、排队、生成、人工修改分别计时 | 明确瓶颈是用户决策、外部模型、Worker 还是返工 |
| 持续使用 | 测试创作者的周重复使用、接受/导出条数和流失原因 | 决定是否建设日更计划、更多模板或第二领域 |

每轮真实试验前设单次及累计费用上限，价格未知时先停在无费用测试。预算预留、有限并发和供应商额度共同控制开销；不把用户免费等同平台无限支付。

在两周试用结束时，用实际数据冻结下一阶段目标，而不是提前声称能够保证日更吞吐、影视级质量或固定单条价格。

### 扩大规模之前必须补齐

- 权限与素材归属、凭据保护、公开服务出站边界。
- 数据库版本迁移；数据库、资产与 Secret Store 的备份恢复演练；恢复时间和可容忍数据丢失窗口需按阶段确定。
- 素材保留期限、用户删除和引用关系清理规则；不能无限保存中间帧和私人上传。
- 每阶段费用、队列积压、Provider 错误和磁盘空间告警，配额与停用开关。
- Worker 崩溃、外部提交未知、迟到结果、下载失败和取消等运行手册。

这是平台运行能力，不是增加素材法务审批或支付系统。

## 7. 技术演进按触发条件发生

| 当前保留的选择 | 触发升级的证据 | 届时评估，而非现在必做 |
| --- | --- | --- |
| 模块化单体 API + 独立 Worker | 独立资源瓶颈、故障域或团队职责确实需要分离 | 拆相应执行服务，不先拆所有业务微服务 |
| 当前直接 LLM Adapter | 第二种协议差异、多平台限流/路由重复实现明显 | LiteLLM 等成熟组件，保留领域网关与单一路由真相源 |
| 持久任务引擎 POC 后择一 | 恢复、取消、等待和运维测试结果 | Celery 或 Temporal；不叠加两套同职责编排 |
| 显式上下文与版本化摘要 | 相关资料增长，查找遗漏可被评测证明 | 检索/RAG；不把向量库当所有项目的默认前提 |
| 外部视频 API + 可选 Blender | 实测调用量、成本和稳定性支持自托管收益 | 云 GPU/自有算力或特定模型部署 |
| 通用模型 + 领域 Prompt/模板 | 形成足够高质量反馈数据，现有方法持续不能达标 | 专项训练/微调试验；不承诺训练必然改善视频质量 |

模型是否升级沿用[模型路线图](2026-09-06-product-and-model-evolution.md)的固定评测、受控试用和回滚规则。可每月检查候选，但不按月份强制换模型。

## 8. 下一开发周期具体做什么

建议规划为一个 1 至 2 周的首周期窗口，若实施复杂度超出窗口则缩小切片并重估，不省略验证。以下引用既有 A/B 工作包，不新增平行任务编号。

- [ ] A1：独立测试数据库/Secret Store/端口，禁止测试访问真实模型；将依赖测试顺序的案例改为独立。
- [ ] A2/A3：先写正确行为的失败回归，修复未确认 Brief、已确认分镜修改、非法字段和版本冲突；同步必要契约/迁移。
- [ ] A4/A5 的高风险部分：修复不存在检查也通过的问题、错误信息脱敏，并明确外部开放必须等待完整权限门。
- [ ] B 的第一条切片：持久 Advisor Run、幂等提交、Worker 执行、状态查询和刷新恢复；注入中断验证，不只演示成功路径。
- [ ] 对应 Creator/Admin 页面反馈和隔离 E2E，记录 Commit、命令、结果、已知问题和下一周期估算。

首周期演示至少包含：正常执行、重复点击、刷新恢复、未确认请求被拒绝、Provider 失败的真实状态。尚未完成的 A/B 工作包保留为 R0 发布阻断，不能以一条 Advisor POC 替代完整生产验收。

## 9. 决策与检阅节奏

- 每周：检阅一个可运行切片，确认质量、失败路径和费用证据；只规划接下来一至两周的详细工作。
- 每月：检查接受率、耗时、成本、用户反馈和技术瓶颈；调整未来一个季度的范围，复核候选模型是否值得测试。
- 每季度：决定继续摩托车深耕、进入第二领域、扩大人数或缩小范围；记录原因和新的资源假设。
- 每个发布门：机器测试、浏览器流程、真实媒体来源和人工质量分别出结论；未执行就标明未执行。

### 需要项目方按时决定的事项

1. 首周期结束前：可持续工程投入和样片检阅节奏；首批车型的最低保真要求。
2. 真实模型/视频试验前：本轮及每日最高支出、允许等待时间、视频 Provider、运行/存储环境。Key 在后台配置。
3. 外部试用前：测试人数与额度、素材保留/删除和备份恢复目标、支持与故障负责人。
4. 第二领域前：首个内容形态、评审人和领域验收集。

这些决策不必今天全部完成，也不应阻挡已经明确的无费用工程整改。未决定的付费或外部开放事项保持关闭。

## 10. 明确停止与延后事项

- 真实主体一致性持续不过关：缩小车型/镜头范围，补资产或更换策略，不靠无限重试扩大支出。
- 费用超出上限：停止试验，分析失败/重试与合格镜头成本；不自动换更贵模型。
- 创作者不愿重复使用：优先访谈和减少操作/返工，不靠铺更多领域掩盖核心体验问题。
- 供应商不可用：按已验证策略切换，或如实阻断；不能用 Fake 替代真实交付。
- 未来一年内也不默认建设：完整剪映替代品、任意车型自动精确重建、全面多 Agent 平台、自有基础模型训练、多微服务集群、全部平台自动发布和收费系统。

下一步应从第 8 节进入开发切片，而不是再写一轮同粒度规划。本文需项目方检阅，具体应用修改仍按下一次明确的开发指令执行。
