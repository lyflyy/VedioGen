## 2. 批次与完成定义

### A：恢复流程可信度

依赖：不需要新 Key。对应复核 F1、F3、F4、F5、F6、F7。

| 工作包 | 实施范围 | 必须通过的验证 |
| --- | --- | --- |
| A1 测试隔离 | 独占测试端口、独立库/Secret Store、显式 Fake 环境、CI 禁止外部 Provider 请求；测试不依赖顺序 | 本机真实服务在运行时 E2E 不复用它；单个 API 测试也能独立执行；生产配置拒绝 Fake |
| A2 中央契约 | 对齐 Brief/Storyboard 运行结构；不丢 subject/action/scene；约束总时长、镜头顺序、资源引用 | 非法时长、空镜头、缺失字段返回 422；模型 JSON 合法但不满足硬约束时不进入可确认状态 |
| A3 版本与确认 | Alembic 迁移、文档唯一约束、不可变版本、Approval 内容哈希、乐观锁 | 草稿 Brief 生成分镜返回 409；旧版本编辑冲突；已确认内容修改创建新草稿；旧 Run 快照不被改变 |
| A4 真实配置 | 草稿/已发布目标正确解析，检查项注册与实测结果；路由失败分类、总尝试和超时限制 | 不存在的 Fixture/检查项不能通过；不允许的错误不 fallback；未知能力不能发布为 verified |
| A5 最小访问边界 | 登录与管理员权限、项目/素材归属、错误脱敏、配置关系与出站目标验证 | 匿名 Admin 为 401、普通用户为 403；跨账号访问失败；模拟上游回显 Secret 后响应和日志均不含标记 |

先补失败回归用例再修改实现；迁移需验证既有项目和加密凭据引用保留。公开访问必须等待 A5；本地诊断环境不视为已多租户可用。

### B：把模型和媒体任务移出请求生命周期

依赖：A1、A2、A3。对应 F2、F7。先做单条 Advisor 任务切片，再迁移分镜和合成。

- 工作流 POC：优先评估 Celery + PostgreSQL Outbox；用相同失败注入场景比较 Temporal，形成一份接受/拒绝 ADR，只采用一个编排方案。验证 Linux/容器部署条件，不能直接把本地 PowerShell 可启动等同生产可用。
- 同一事务保存输入版本、Run 和 Outbox；前端获得稳定 Run ID，刷新、断网或重复点击均可恢复；幂等键限定账号/操作/输入哈希，同键不同输入返回冲突。
- Worker 保存 Attempt、请求意图、供应商任务 ID、结果和错误；耗时网络调用不持有业务数据库长事务。事件持久化，初期轮询即可。
- 记录路由、部署参数、Prompt/Schema、ContentPack、素材哈希和工具版本快照；凭据只记录引用/版本，不复制明文。已撤销凭据立即禁止使用，不能为了快照重放绕过撤销。
- 建立有限重试、退避、超时和取消。供应商缺少幂等/查询能力时，把未知提交状态交给对账或人工处理，不声称绝对不重复计费。
- 增加费用预留/结算/释放；估算价、账单价与未知价分开。没有价格配置时，真实试验必须有明确额度，不显示免费。

完成门：模拟 60 秒模型请求时 API 在受控本地测试的 2 秒内返回 Run ID；并发同一幂等键只建一个逻辑 Run；Worker 被杀后可恢复；外部已接收后中断不会盲目重提；取消后迟到结果不进入交付；迁移后的 UI E2E 可刷新恢复。2 秒是验收目标，不是现状或外部网络 SLA。

### C：前置创意顾问与内容包落地

依赖：A2、A3、B。主要对应 F6。

- 输入上下文包括 AccountBrief、用户消息、已处理素材、来源可追踪 Facts 和硬 Constraints；上传视频应有抽帧/观察记录，不支持时明确提示。
- 不确定时先澄清；三套方案不是任何场景都必须硬凑的输出。搜索结果记录来源和时间，与用户事实分开，未经搜索不得声称掌握平台当前趋势。
- Brief 可以确定性编译已选择方案，保留来源和字段覆盖记录；新增生成文字部分才另记真实 Invocation。
- 建立 ContentPack Registry，摩托车与一个育儿演示包使用同一核心状态机，领域 Prompt 和评分规则独立。
- 质量门由确定性校验、可解释模型复核、用户确认组合，不以单一 LLM 自评分代替真实性证据。

完成门：张雪 800X 的最后镜头保持皮衣骑手高速驾驶，不能被额外 CTA 镜头挤走；春风 800MT 保持四段用户要求的内容顺序；总时长和语言符合确认值；无可靠另一侧资产时对真实 360 度保真提出澄清；育儿包输出不出现固定摩托车 CTA。模型升级使用同一输入集比对结果、时延、Token 和失败率，先测试再发布。

### D：真实单镜头生产切片

依赖：A、B；C 提供通过确认的真实测试分镜。外部生成镜头需要用户选定 Provider 与额度。

- Planner 将已确认分镜编译为不可变 ShotManifest；按策略独立检查能力、输入资产和资源预算。
- 单一视频 Provider Adapter 实现提交、查询、取消能力声明、下载和失败归一化；不支持取消时明确“本地停止交付，供应商可能继续计费”。
- 对象存储/直接文件上传二选一按 Provider 能力实现；Worker 下载验证来源、大小、可解码性、哈希及媒体元数据，产物归属可追踪。
- 用用户视频拼接或真实上传图的 image-motion 验证无视频模型路径，但必须如实标记类型，不冒充生成驾驶镜头或 Blender 360 环绕。

完成门：用户参考图生成一个真实 5 至 8 秒镜头；输入哈希、Run/Attempt、Provider ID、输出文件、费用状态可追溯；超时、限额、任务失败、重复回调/查询、失效下载 URL 均能处理。人工比较真实车型身份和结构，无合格结果不得只因下载了 MP4 就算通过。

### E：多镜头交付与 3D 质量门

依赖：D 通过。

- 多镜头并发受配额限制；单镜头重试只重算目标镜头与必要的下游合成，产物版本不覆盖。
- FFmpeg 消费真实 Shot Artifact；字幕、旁白/音乐和镜头时间轴遵守确认后的计划，不能沿用固定 6 秒预览。
- QC 验证可解码、比例、帧率、时长、缺失镜头、黑帧、音画同步和字幕安全区。车型保真、叙事和视觉质量保留人工验收。
- 真正 360 度分支另需车型资产、多角度参考和固定 Blender 环境；汽车课程中的车门/安全带等部件不机械套到摩托车。

完成门：两个用户样例完成“输入 -> 顾问讨论 -> Brief 确认 -> 分镜确认 -> 真实逐镜头生成 -> 局部重试 -> 合成 -> 质检 -> 下载”的浏览器验收，记录实际成本和等待时间。Blender 资产未准备好时明确该分支未验收，不阻断已支持策略的独立交付。

## 4. 交付证据与停止条件

每批次记录代码 Commit、迁移版本、自动测试命令与结果、浏览器截图/Trace、输入输出版本及未通过事项。真实模型试验额外保存 Request ID、Token、产物哈希和费用来源；不得提交 Secret、签名 URL 或私人素材明文。

CI 使用隔离 Fake/Mock，真实 Provider 测试是单独的预算受控流程。测试通过与艺术质量通过分别报告，不混用“全流程通过”。

以下问题尚需项目方确认，但不阻碍 A/B 的工程整改：首个视频 Provider、部署地区和 Worker 环境、单条样片最高成本和最长等待、真实车型保真等级与可用 3D/多角度资产、旁白需求。暂不承诺日更吞吐或具体排期，先测真实调用和渲染性能。
