# 本地优先、逐镜头制作的 MVP 调整设计

- 日期：2026-09-11。
- 状态：待确认。本轮交付设计，不代表能力已实现或样片已通过。
- 目标：内部创作者通常只输入文字，平台帮助决策、准备素材并完成可用视频；先取得人工认可的 80 分，不以播放测试替代质量验收。
- 关系：细化已接受的 ADR-0003 混合路线和 2026-09-07 本地优先计划；建议调整近期顺序，不撤销既有关键镜头要求。
- 依据：[GitHub 源码调研](../research/2026-09-11-video-workflow-practices.md)、[原项目真实执行](../discussions/2026-09-10-original-storyboard-execution.md)。本轮未重新运行外部项目或进行模型效果对比。

## 1. 调整结论

从“脚本完成后为各镜头配图，统一图生视频，再拼接”调整为“创意与可行性共同规划，准备可靠参考，各镜头选择制作方式，先试关键镜头，再完成音画”。

不是把平台改成手工剪辑软件，也不是从头开发 AI 导演框架。用户关注主题、风格和结果；素材选择、参数适配、任务调度由平台承担。

保留 Next.js、FastAPI、现有 GPT 网关、ComfyUI/Wan、Blender、FFmpeg、单机后台任务、局部重做与片段复用。不新增工作流引擎、多租户、正式版本审批或内容合法性校验；凭据保护、文件检查和有限重试继续保留。

当前已证明本机能生成并交付视频，尚未证明任意真实车型、准确 360 度、复杂驾驶都能仅凭文字自动达到 80 分。原生推理尺寸和合成输出尺寸必须分开记录。

## 2. 产品流程

```text
输入想法
  -> GPT 结合现有素材与执行能力推荐方向
  -> 平台准备主体参考、镜头计划与声音计划
  -> 用户确认一份创意方案，可用自然语言修改
  -> 平台试制最难或最重要的一镜
  -> 用户确认关键效果，或选择明确说明的替代方案
  -> 平台完成其余镜头、音画合成与技术检查
  -> 预览 / 用自然语言指出问题 / 单镜重做 / 下载
```

- 默认一份推荐方案，不强制用户逐镜挑素材、选模型、填时长。已验证的低风险模板后续可省略关键试片确认，不省略用户要求发生变化时的确认。
- 复用现有策略、分镜、生成和成片页面；流程分工清晰，但不要求新增一批页面。
- 策略页给出内容诉求、节奏、关键画面、可行性和推荐理由，不承诺抖音传播成绩。
- 分镜默认展示画面预览、简短描述、预计时长和待处理事项；参考选择、制作方式和模型参数收进高级设置。
- 生成进度显示真实阶段、已完成镜头和可用结果；没有实测时不编造倒计时。展示决策摘要，不展示或模拟模型私有思考过程。
- 用户固定素材发生冲突时一次性集中提示；平台推荐的错配由平台重新准备，不逐项要求用户修参数。
- 失败只重做受影响镜头；保存不触发生成，生成中刷新可恢复状态，不因重复点击重复提交。

## 3. 按镜头选择路线

| 镜头需求 | 推荐制作方式 | 不可越过的边界 |
| --- | --- | --- |
| 车灯、仪表、车身细节 | 同车型高清图裁剪与轻运镜；有准确模型时可用 Blender | 静态图片动画不能冒充发动机运转或真实驾驶；仪表读数不交给模型随意重绘 |
| 整车展示、有限侧向运镜 | 同车型实拍片段，或经试片验证的本地图生视频 | 不将有限视角变化标为精确完整 360 度 |
| 准确 360 度 | 匹配车型的真实环绕视频，或检查过的准确几何 + Blender 轨道 | 单图、生成的多视图、相似车型几何都不能证明真实背面结构 |
| 皮衣骑手驾驶 | 匹配车辆与骑手的实拍片段优先；本地 I2V 做有预算的试片 | 重点检查服装、车型、车轮、接地与肢体；不得用别的赛车图填空 |
| 沙漠、涉水抬头、山林远拉 | 每个动作独立试片；合适实拍或已验证场景可复用 | 缺素材与失败不等于自动删除动作或改成静态图；改要求需确认 |

路由依据是镜头要求、素材条件、执行器能力和可接受质量，不是固定“所有镜头优先某模型”。现有 `sourceStrategy` 继续作为执行字段，不另建一套重复策略枚举。尚未接通的实拍检索或模板不能在 UI 标为已可用。

对“只有文字 + 真实车型”：先检索/复用准确资料，再补缺口。搜索到图片不代表搜索到了视频；知道车型名称也不代表拥有可渲染几何。平台无法补足时，提供可行选项，而不是退回一串参数错误。

## 4. 最小数据与编排设计

| 增量 | 最小内容与职责 |
| --- | --- |
| 主体参考包 | 主体 ID、车型/版本、配色、关键可见特征、参考素材 ID、来源及确认状态；骑手作为独立主体关联 |
| 素材观察结果 | 实际看到的视角、颜色、人物、部件、清晰度和可用区域；不确定项标未知，不能仅凭视觉猜测就认证车型 |
| 镜头制作计划 | 沿用 Shot，补充必需画面/动作、主体引用、路线理由、参考来源、预检结果、关键试片标记与验收条件 |
| 素材选择归属 | 区分用户固定、平台推荐、历史未知；平台可重选错误推荐，用户固定和历史未知先提示，不静默覆盖 |
| 声音计划 | 旁白是否需要、音乐/环境音/音效来源、剪辑节奏及必需音轨；最终实际音轨必须可听见 |
| 运行记录 | 沿用现有任务，记录实际输入、执行方式、产物、耗时和重试次数；只做执行追踪，不建正式内容版本树 |

建议调用顺序：GPT 提出创意及镜头意图，后台用已配置能力检查可执行性，素材准备补齐证据，再产生可执行计划。模型建议必须经过现有参数校验，不能直接运行模型生成的任意脚本或安装依赖。

视觉观察分批覆盖实际候选并缓存；缓存键包含素材内容摘要、分析模型/提示规格，参考图变化后失效。GPT 网关是否支持真实图像输入须通过现有配置验证；不支持或 429 时标为未检查，沿用冷却，不假装完成视觉检查。

技术就绪与内容就绪分开：可解码、时长正确只是技术就绪；参考是否匹配、动作是否具备条件属于内容就绪。必需主体冲突或准确 360 度缺资产时暂停相关制作并提出建议；一般画质不确定先进入试片，不将所有不确定性变成阻断。

旧项目兼容：新字段可选，保留现有绑定和成片。用户主动启动重新规划时才生成建议；不能批量改写旧分镜。继续使用当前存储和单进程执行机制，GPU 推理与 Blender 串行占用资源。

## 5. 参考准备与声音

参考准备从“项目有图片就结束”改为“按镜头缺口准备”：同车型、同配色优先，保留主体关键部件与运动空间。推理前完成竖屏构图、尺寸与边缘检查；生成式补背景作为需验证的可选方案，不默认为已安装可用能力。保留原图，避免反复裁剪。

声音按内容类型处理：摩托车宣传片优先音乐节拍、动作与环境音，旁白可选；育儿解说等以后按实际配音长度组织画面。复用已有 Piper 和 FFmpeg，不重复建设语音引擎。

近期可建立少量内部可用音乐/音效素材包并由平台推荐；素材包未备齐就是明确依赖，不能把静音 AAC 当成声音设计完成。引擎声不宣称是某车型真实录音，除非实际来源支持。混音需检查响度、峰值、对白可懂度与结尾截断。

## 6. 分批交付与验收

### A. 先改素材与镜头决策

- 修改 `storyboard_jobs.py::prepare_images/assign_assets`：按镜头补缺，区分素材选择归属，输出可理解的建议。
- 修改 `gateway.py::match_storyboard_assets`：消除只向视觉请求提供前四张图的覆盖缺口；候选分析可复用，响应引用必须在已检查候选内。
- 在现有计划构建与就绪检查中增加路线理由和必需条件；先支持已接通执行方式，不扩建通用自动路由平台。
- 验收：第五张之后的匹配图可被正确采用；已有无关图不会阻止补素材；平台错配能修复，用户固定不被静默替换；429 不循环调用；缺准确几何不启动伪 360 度。

### B. 做出一条混合制作质量基准

- 在现有红色张雪 820RR 项目分镜上提出新计划，尽量复用可用原片；保持最终皮衣骑手驾驶要求，不擅自加结尾镜头改变顺序。
- 先解决参考一致和推理前构图，再试驾驶关键镜头；准确 360 度仍缺资产时如实暂停该要求，有限环绕只有经用户接受才可替换。
- 加入实际音乐/音效和必要字幕，从浏览器完成确认、生成、局部重做与下载。不能靠开发者在平台外手工做片通过验收。
- 建议每个关键镜头先生成一个候选，单镜最多两次本地尝试；总 GPU 时间上限由本机试跑记录与用户等待要求确定，配置前不开展无人值守批量重试。付费视频回退默认关闭。
- 验收分为文件/流程自动测试和人工画质评审。沿用 [80 分评分与硬失败条件](2026-09-06-internal-mvp-reset.md#3-80-分怎么判断)，目前没有通过结论。

### C. 验证可复用，再扩内容类型

- 再用春风 800MT 的沙漠、仪表、涉水抬头和远拉要求验证；失败项目明确标出支持边界，不把张雪样片通过推导为全品类通过。
- 固定少量样例比较可用镜头比例、主体一致性、等待时间、GPT 用量、GPU 分钟和人工干预次数；本地不等于零成本。
- 达到稳定产出后，将有效镜头组合、声音节奏与提示规范整理为摩托车内容包；再增加一个不同节奏的解说类内容包，验证通用核心无需依赖车辆或 Blender。
- 日更能力以连续实际生产记录验证；不在缺少吞吐实测时承诺每天条数或单片时延。队列扩容、更多模型和硬件升级只针对测出的瓶颈。

## 7. 复用原则与待决事项

借鉴 MoneyPrinterTurbo 的分阶段产物和复用、NarratoAI 的素材理解、Short Video Maker 的音画时长联动；继续采用 ComfyUI 推理与 FFmpeg 合成。OpenCut 当前主仓重写中，暂不整体 Fork。参考的是具体机制，不是 Star 数量或未经实测的宣传效果。

当前建议先执行 A，不先换模型、重做 UI 框架或下载更大权重。B 的关键分岔是：准确完整 360 度作为必需镜头继续寻找素材/几何，还是用户明确接受有限环绕。该项未确认前保持原要求，其他素材与路由设计不必等待。

本轮未修改生产代码、未调用模型、未重新生成视频。新方案需检阅，实施时按 A/B/C 分批记录实际结果，不把本设计文档当作已完成能力清单。
