## 当前判断

项目已具备产品定位、首期用户、典型输入、两个确认节点、AI 创意顾问流程、平台总体架构、大模型工具编排方式、两个真实内容样例和初步成本模型。

现在可以准备并执行隔离的技术探针，但还不适合建设完整 MVP。进入 P0 开发前还需冻结首版输出、交互、模型接入方式和验收标准；进入 MVP 开发前还需完成数据与工具契约、状态机、界面设计和测试策略。

## 建议的 P0 默认值

为了减少下一轮讨论成本，建议以此作为待确认基线：

| 项目 | 建议默认值 |
| --- | --- |
| 平台 | 抖音优先，只下载 MP4，不做自动发布 |
| 画面 | `9:16`、`1080 x 1920`、30fps |
| 时长 | 20 至 30 秒，4 至 6 个原子镜头 |
| 语言 | 简体中文 |
| 交互 | 左侧 AI 对话、中央策略/Storyboard、右侧事实或镜头设置 |
| 确认 | 先确认 Creative Brief；脚本和 Storyboard 同页二次确认；单镜头可改写或重生成 |
| P0 用户 | 本机单用户，不做登录、计费和团队权限 |
| 模型 | 托管 API 优先，每类能力先接一个供应商 |
| 视觉路线 | 参考图/图生视频为主，Blender 作为独立对比探针 |
| 输出 | H.264 MP4、AAC 音频、硬字幕 |
| 样例 | 张雪 800X 与春风 800MT |

## 开发门

### Gate P0：允许开始垂直切片

以下条件同时满足即可开始：

1. 上述 P0 默认值被接受或修订。
2. PRD、体验流程、UI 四份规格和 P0 计划通过。
3. 至少一个 LLM 和一个视频生成服务可以在开发环境调用。
4. 两个样例的验收清单明确。
5. Projects、Strategy、Storyboard、Admin Routing 四个关键线框通过。

### Gate MVP：允许扩展为平台产品

P0 必须实际跑通完整链路，并能展示脚本/Storyboard 修改、单镜头重试、最终成片和成本记录。中央 Schema、状态机和关键线框图通过后，才扩展登录、项目历史、多供应商、配额和部署。

## 时间估算

在上述假设成立、模型 API 可用且不训练自有模型的情况下：

- 核心文档评审与供应商/保真标准确认：1 至 2 个讨论轮次。
- P0 垂直切片：包含企业化 UI 基础和模型管理后台后约 11 至 18 个工作日。
- P0 评审和契约收敛：约 2 至 4 个工作日。
- 可供小范围测试的 MVP：P0 通过后约 3 至 6 周。
- Blender 高质量 3D 路线：取决于模型和场景资产，可与平台 P0 并行验证，不纳入首条 AI 视频链路的阻塞条件。

如果改为本地部署大模型/视频模型、从零制作摩托车 3D 资产或首期就支持多人公网使用，时间需要重新估算。

## 推荐执行顺序

1. 项目方评审 PRD v0.1、体验 Spec、UI 四份规格、P0 计划、ADR-0004 与 ADR-0006，并修改 P0 默认值。
2. 确认真实车型保真标准和首个 LLM、搜索、视频 Provider 路径。
3. 四个关键线框和 Token 评审通过后，建立工程脚手架、组件目录和两套 Shell。
4. 开发门通过后先跑通张雪 800X 单条链路。
5. 用春风 800MT 验证流程没有针对第一条内容硬编码。
6. 记录质量、耗时和成本，修订 Schema 与默认策略。
7. P0 通过后进入完整 MVP 开发。
