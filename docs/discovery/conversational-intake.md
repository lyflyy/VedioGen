# 对话式输入与确认流程

- 状态：草案
- 建立日期：2026-09-05
- 依据：首批两个摩托车内容示例

## 用户输入特点

用户会在一段自然语言中混合车型、宣传语、镜头、环境、人物和动作，不会主动填写完整制作参数。例如：

- “张雪 800X 最酷视频，要车辆细节、360° 3D 环绕，最后是穿皮衣的人高速骑行。”
- “春风 800MT，真正的越野之王，先环绕，再去沙漠、涉水和山林。”

创作入口应以一个主输入框和可选素材上传为主。系统从自然语言提取结构，自动补全低风险参数，并在写脚本前主动给出创意建议，而不是直接执行用户最初的想法。

## 创意顾问前置流程

```text
用户想法与素材
  -> 账号目标、受众和 Project Facts
  -> 搜索与 Evidence Pack
  -> 内容机会诊断
  -> 2-3 个 Strategy Proposal
  -> 用户讨论、修改或合并
  -> Creative Brief 确认
  -> 脚本与 Storyboard
```

Proposal 至少说明 Hook、一个核心承诺、视觉证明、节奏、情绪峰值、结尾动作、所需素材和相对资源等级。系统可以推荐，但不能用“预计爆款”或保证播放量替代可解释判断。

## 解析结果

首次解析至少得到：

- 内容方向、车型名称、可能的品牌与年款。
- 视频目的、宣传语、整体气质和节奏。
- 用户明确要求的场景、动作、人物和镜头顺序。
- 用户提供的图片、视频和其他参考素材。
- 必须保留的原话，例如“真正的越野之王”。
- 不得凭空补写的事实，例如功率、极速、价格和配置参数。
- 需要用户确认的歧义，以及已经被用户明确确认、不能再由搜索结果覆盖的项目事实。

## 原子镜头扩展

用户描述的是创意段落，后台执行的是原子 Shot。一个 Shot 只承担一种主要景别、摄像机运动和生成策略，才能独立预览、替换、计费和重试。

例如“车辆跑在沙漠里，尘土飞扬，转速表特写”应拆成：

1. 沙漠环境中的外部追车镜头。
2. 转速表/仪表的微距特写。

“聚焦车辆细节”可以扩展成灯组、刹车、悬挂、油箱或排气特写，但扩展前要受 Reference Pack 约束，避免生成不存在的结构。

## 自动默认值

首期可以在用户没有说明时采用以下默认值，并允许在确认页修改：

- 抖音竖屏 `9:16`，`1080 x 1920`，30fps。
- 20 至 25 秒，4 至 6 个原子镜头。
- 电影感、高对比、快节奏剪辑。
- 低沉短句旁白、发动机/环境音和音乐混合；可一键关闭旁白。
- 片头短标题，片尾车型名或一句收束文案。
- 人物默认佩戴黑色全盔和黑色皮衣，减少跨镜头人物一致性问题。

这些默认值不应触发阻塞式提问。用户可以在 Storyboard 确认页直接修改。

## 两个确认点

第一次确认锁定 Creative Brief，解决“做什么、为什么做和采用哪个方向”。第二次确认在同一页面完成脚本与分镜，解决“具体说什么、每个镜头怎么拍”。只有第二次确认后才执行高成本媒体生成。

为了支持账号日更，脚本与分镜仍在同一个页面确认：

1. 顶部显示识别到的车型名称、AI 视觉参考和全局风格。
2. 中间按时间顺序展示镜头缩略图、时长、画面说明、旁白/字幕和声音。
3. 每个镜头支持重新生成、替换素材、改文案和删除。
4. 页面显示预计生成时间与资源消耗。
5. 用户点击“确认并生成”后，保存不可变 Storyboard 版本并启动高成本任务。

只有车型识别存在明显歧义且用户尚未确认，或总时长超出系统限制时，才在进入确认页前追问。用户一旦确认车型名称，后续搜索只能补充资料或报告冲突，不能再次改写车型身份。声音、音乐、色调和字幕样式使用默认值即可。

## 镜头策略路由

系统先根据用户素材选择策略，再根据质量和成本降级：

1. 有可用用户视频时优先剪辑用户视频。
2. 有多角度图片时优先图生视频。
3. 有合适 Blender 资产时，360° 环绕、机械特写和可控产品镜头优先 3D。
4. 动态越野、沙尘、涉水、骑手和无人机镜头优先参考图生视频或混合合成。
5. 视频生成失败时，可退化为高质量图片运动镜头，保持整条视频可交付。

用户不需要看见模型供应商或 Blender 参数，只需要看到画面预览和可修改的创意含义。

## 从样例得到的产品要求

- 用户可以指定部分镜头，AI 自动补全开场、过渡和收束。
- 用户指定的镜头顺序默认保持不变。
- 一个自然语言段落可以拆成多个原子 Shot。
- 宣传语与事实参数分开存储；宣传语保留，参数不能凭空生成。
- 车型 Reference Pack 在所有镜头间共享。
- 最终高速/大场面镜头通常承担情绪高潮，分配更长时长和更强音乐节拍。
