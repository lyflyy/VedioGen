# 模型配置与编辑

日期：2026-09-12。状态：已实现，内部 MVP 增量。

## 配置边界

沿用现有 Provider / Credential / Deployment / Routing 分层，不新增平行配置存储。

| 管理入口 | 可编辑内容 | 约束 |
| --- | --- | --- |
| 模型平台 | 名称、适配器、Base URL、区域、启用状态 | 平台 ID 不变；修改地址或适配器前确认影响 |
| API Key | 别名、替换 Key | 所属平台不变；编辑时 Key 不回显，留空保留原值 |
| 模型部署 | 名称、平台、物理模型 ID、Key、能力标签、超时、上下文上限 | Key 只能选择所属平台的有效凭据 |
| 能力路由 | 各业务能力使用的默认模型 | 沿用现有路由页；新建模型不会自动抢占默认路由 |

平台适配器仅提供已有实现：OpenAI-compatible、fal-video、隔离测试 Fake。填写平台地址并不等于自动支持所有厂商协议；能力标签也不等于已实现对应生成适配器。

## 操作流程

1. 添加或编辑平台，输入 HTTP(S) Base URL，不含 Key、查询参数或完整的 `/chat/completions` 等接口路径。
2. 添加该平台的 API Key，或修改已有凭据。服务端加密存储，只返回别名和尾号。
3. 添加或编辑模型，选择平台及对应 Key，填写供应商实际模型 ID 和参数。
4. 保存连接相关变更后执行能力探测；通过后可用于已有路由。新模型需在能力路由中选择。

超时范围 1 至 600 秒；上下文上限可空，否则至少 1；能力标签不能为空。创建及编辑均由服务端校验，错误显示在表单内。

## 状态契约

- 仅修改平台名称、模型名称或 Key 别名，不清除已就绪状态。
- 修改平台 Base URL / 适配器，使其关联模型回到草稿，已禁用模型保持禁用。
- 实际替换 Key，使关联模型回到草稿，清除旧 Key 的成功记录与冷却状态。
- 重复提交相同 Key 不解除 429 冷却，不能借保存操作绕过调度保护。
- 修改模型平台、物理 ID、凭据、能力或参数后回到草稿，保留部署 ID 与已有路由引用。
- 禁用平台不能探测；重新启用不表示上游一定可用。
- 探测成功返回前检查模型与平台版本；探测途中配置已变化则返回 409，要求重试。
- 探测只验证当前适配器已有的连通/结构化输出能力，不保证所有勾选能力均能真实生成。

## 接口

- `POST /api/v1/admin/model-providers`、`PATCH /api/v1/admin/model-providers/{id}`。
- `POST /api/v1/admin/model-credentials`、新增 `PATCH /api/v1/admin/model-credentials/{id}`。
- 凭据 PATCH 仅接受 `alias`、可选 `secret`；省略 secret 保留原 Key，显式空串由接口拒绝。
- 原 `POST /api/v1/admin/model-credentials/{id}/rotation` 复用编辑逻辑，仍要求新 Key。
- `POST /api/v1/admin/model-deployments`、`PATCH /api/v1/admin/model-deployments/{id}`。
- 原凭据连通性测试、模型能力探测、路由与调用日志入口保留。

## 界面与验证

复用现有企业管理导航、表单、列表、Lucide 图标与提示组件。配置表单桌面双列、手机单列，标题独占一行；编辑项预填，保存/取消集中排列。Key 始终为空的密码输入框。

API 回归覆盖原子校验、跨平台凭据拒绝、配置失效、相同 Key 的冷却保留，以及新参数传入探测与网关。浏览器覆盖新增、编辑、刷新回显、取消、探测、Key 不泄露、响应式与可访问性。测试不替换真实凭据，不把 Fake 或 mock 调用称为上游真实调用。
