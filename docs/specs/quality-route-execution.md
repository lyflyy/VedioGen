# 混合制作增量执行契约

- 日期：2026-09-11。
- 状态：已实现基础增量，真实新文字入口因中转站 429/502 尚未验收；复用脚本的本地展示成片已交付，动态试片画质未通过。见 [实施记录](../discussions/2026-09-12-quality-route-implementation.md)。
- 沿用当前 Shot、DocumentRow、GenerationRunRow，不迁移框架或添加分布式工作流。

## 参考与镜头

- 图片候选每批最多四张，逐批观察可见主体、配色、视角、部件及限制；所有候选 ID 必须有对应观察。每批结果保存为 `reference-observation` 文档，键包含文件内容摘要、素材说明、路由、模型和分析版本。
- 镜头匹配使用完整观察结果，返回既有 ID、来源策略、理由、是否需要试片、精确环绕要求和阻断原因。无匹配参考必须返回空，不能按列表位置填充。
- `referenceChecked` 只表示完成参考观察/匹配，不代表权威认证车型或已看过生成视频。新真实视觉能力仍受模型通道可用性约束。
- `selectionOwner` 分 `platform`、`user`，旧项目缺省为历史未知。平台推荐可以纠正，用户固定不静默替换；页面上传、裁剪与应用到同类镜头均标记用户选择。
- `strategyOwner=platform` 时才自动应用建议路线；手动选择策略不被模型静默覆盖。
- UI 切换制作方式时保留类型兼容的素材，例如图片运动和参考图生视频共享原图；切换到视频或几何来源时才清空不兼容引用。
- 制作计划保存在 Shot 的 `productionPlan`。更改画面、运镜或素材会使已有计划失效，`requiresPlanning` 阻止沿用旧检查。通过自动准备重新检查后解除。
- 已检查、无冲突、未改动的参考复用，整片提交不重复匹配。搜索已入库且文件存在的同 URL 素材不会重复下载。
- 官方素材初期最多抽样三个配色组、每组两个视角，另准备两个细节候选，避免首组白色素材阻止匹配红色要求；后续匹配必须保持成片主体配色一致。这是有限候选集，不是任意镜头素材搜索能力。精确几何与驾驶实拍仍需实际来源。

## 关键试片

- 技术就绪与是否已接受关键试片分开；单镜可执行不代表整片可直接生成。
- `POST .../material-runs?generate=true` 完成准备后，若技术条件齐全但关键镜头待确认，先创建一个单镜头试片，返回 `phase=reviewing-preview`、`previewShotId`、`previewGenerationRunId`，不创建整片任务。
- UI 定位该镜头并显示真实试片状态；采用复用既有机制，结果转为视频素材后整片不再次推理该镜头。
- 普通完整素材计划仍可一键启动整片；素材准备接口本身不直接创建付费云视频任务。
- 准确完整 360 度的计划不能以图片运镜或普通图生视频执行。几何身份尚未自动认证，不将 GLB 文件可解码等同于车型准确。

## 画幅与声音

- 新本地 I2V 计划可用 `referenceFraming=portrait-soft`，推理前用 Pillow 准备目标画幅，并记录实际参考摘要；原图不覆盖。
- 新本地任务默认 `decodeMode=tiled`，使用 ComfyUI 核心 `VAEDecodeTiled`（空间块 256、重叠 64、时间块 16、重叠 4）；管理后台可选整段解码。旧任务快照缺少此字段时仍沿用原解码方式，不在恢复中偷偷改参数。
- 透明底产品图采用统一深色底，不复制主体生成模糊重影；普通照片可采用柔化背景保留完整主体。这不是生成式补景，也不是原生竖屏实拍。
- `soundPlan` 为 `{background: none|local-pulse, narration: boolean}`，分镜页保存后由一键生成遵循；用户保存过的声音方案不被后续匹配覆盖。
- 本地电子节奏由 FFmpeg 生成，120 BPM，包含低鼓、贝斯、轻和弦和淡入淡出，不宣称真实车型引擎录音。旁白沿用 Piper，禁止截断超长旁白伪装成功。
- 用户上传背景音频优先于内置节奏。单镜头试片不混入整片音轨，最终统一合成。
- 脚本导出为 Markdown，包含镜头时长、画面、运镜、字幕、旁白、制作方式和素材文件名，不导出凭据或私有文件路径。
- `image-motion` 当前固定执行原图居中轻推近，不解析任意自由文本运镜。新脚本提示词约束此边界，旧脚本导出区分画面/运镜意图与实际执行；不能将镜头视角变化的文字当作已渲染动作。

## 失败与复用

- 匹配失败前已成功生成的 GPT 脚本保存在准备任务的 `draftScript`。相同消息与 Brief 的显式重试复用脚本，避免重复调用脚本模型。
- 429 继续使用既有持久冷却/额度暂停，不通过改 Key、盲切路由或反复 POST 绕过。
- `POST /projects/{id}/copies` 是明确的脚本与素材复用操作。复制为独立草稿、重新映射项目/镜头/素材 ID，保留来源信息，不复制活动任务或伪造一次新的模型调用。
- 副本引用同一不可变素材文件，编辑分镜不修改原项目。尚无独立物理文件去重/回收系统，未来实现删除时必须检查所有引用。
- 项目头部的复用入口禁用于未保存草稿。原始 GPT 入口失败与从既有脚本继续制作必须在验收记录中分开。
- 用户明确改为现成视频或 GLB 时，清除旧图片匹配计划，按既有媒体/模板契约检查可执行性；本轮未增加视频逐帧语义验证或几何身份认证，不能给这类手选素材虚标视觉检查通过。

## 验收层次

自动测试覆盖缓存、候选完整性、固定素材保护、计划失效、关键试片、声音非静音、脚本复用和旧流程回归。真实验收额外记录模型实际请求、素材、原生推理尺寸、片段、合成、浏览器播放/下载和人工画面观察。
