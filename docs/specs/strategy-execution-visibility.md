# 策略生成过程可见性

日期：2026-09-13。状态：内部 MVP 已实现。

## 目标与界面

替换固定的“正在形成创意判断 / 整理车型事实、视觉机会和制作约束”。首次生成、重新生成、失败时均保留创意对话与补充要求输入框。

策略主区上方显示生成状态、等待秒数及四个环节；最近三条实际调用记录可展开，全部历史仍在项目执行日志页。桌面进度横排，手机双列；长错误说明、模型 ID 和请求 ID 自动换行。复用既有设计 token、Lucide 图标及管理/创作导航。

## 状态来源

| 环节 | 数据依据 | 不宣称的能力 |
| --- | --- | --- |
| 项目输入 | 已加载的项目消息与素材数量 | 不把数量当成事实核验完成 |
| 模型调用 | 持久化 ModelInvocationRow 的 calling / failed / succeeded | 不假称模型在联网搜索、建模或生成图片 |
| 结构化校验 | 网关成功记录代表输出已通过现有本地 Schema 校验 | 不虚构校验百分比或定时推进步骤 |
| 建议保存 | 创意建议接口成功返回、结果已写入数据库 | 不以模型 HTTP 成功替代应用结果保存成功 |

生成期间每 2 秒获取本项目 creative-advisor 调用记录；等待秒数依据调用记录时间计算，完成/失败后停止轮询并最终刷新一次。终态调用展示持久化耗时、Token、上游请求 ID 和错误码。日志请求失败单独提示，不因日志服务失败自动再次调用模型。

本轮调用使用提交前的记录 ID 集合作为边界，避免把上次的成功/失败标成当前结果；已有 calling 记录不排除，兼容刷新后复用正在执行的请求。最近调用列表明确是历史记录，不是模型内部思考。

没有新增任务队列或第二套日志库；没有新增模型思考输出、SSE 文本流或任意提示词编辑器。当前创意建议仍使用原有同步提交与请求去重逻辑。

## 接口增量

`GET /api/v1/projects/{projectId}/activity` 新增可选 `capabilityAlias` 查询参数。与 category 过滤组合使用，在分页前过滤，避免新的视频/脚本记录挤掉策略调用。

策略查询：`?category=model&capabilityAlias=creative-advisor&pageSize=10`。沿用项目范围及原有脱敏规则，不新增 Key 或完整请求提示词输出。

## 反馈与恢复

- 生成时可编辑补充要求草稿，发送与采用操作禁用，避免同一页面重复调用。
- 成功回包只清除本次已提交且未继续编辑的文字，保留等待期间新增的草稿。
- 失败保留输入，允许直接发送调整后的要求或重新生成；相同反馈已成功保存但模型失败时，重试不重复追加消息。
- 重新进入页面发现最近一次真实策略调用失败时，展示历史错误并要求显式重试，不自动消耗模型额度。
- 有旧建议时重新生成不会删除旧建议；等待或失败明确标注保留上一轮建议。
- 不提供虚假的“取消模型”按钮；当前同步上游调用尚无可靠取消计费保证。
