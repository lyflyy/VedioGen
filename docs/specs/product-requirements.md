# 产品需求文档 v0.1

- 状态：待项目方评审
- 版本：0.1
- 日期：2026-09-05
- 产品负责人：项目方（具体负责人待指定）
- 首期范围：普通自媒体创作者的抖音摩托车日更视频

## 1. 产品定义

VedioGen 是一个 AI 辅助的社交媒体视频创作平台。用户提供一句想法、文字或可选图片/视频，平台先以创意顾问身份帮助判断内容方向，再生成可确认的脚本和 Storyboard，最后调用用户素材、AI 媒体、Blender、TTS 和 FFmpeg 等工具生成成片。

平台不是固定模板库，也不是把用户提示词直接转交给单个视频模型。核心价值是：

- 帮用户做创意决策，而不只是执行指令。
- 把零散想法转换为可确认、可执行、可局部修改的镜头计划。
- 根据镜头选择不同生成方式，并记录质量、耗时和资源消耗。
- 以通用平台核心加垂直内容包支持后续母婴、育儿等方向。

## 2. 已确认约束

- 首期用户是普通自媒体创作者。
- 核心使用场景是账号日更。
- 首期不设计付费、订阅或计费功能，但内部必须记录资源消耗。
- 用户通常只提供思路和文字，也可提供照片、多角度图片和视频。
- 默认制作真实车型；只有用户明确要求时才进入概念车型模式。
- 用户在高成本生成前确认内容。
- 首期优先抖音，输出下载文件，不做自动发布。
- 首期不建设面向用户的素材授权审核、品牌法务审批或法律风险判断流程。

## 3. 目标与非目标

### 3.1 P0 目标

1. 从自然语言稳定提取项目事实和创作意图。
2. AI 主动给出 2 至 3 个有明显差异的创意策略，并解释适用条件和取舍。
3. 用户能通过对话选择、合并或修改方向，锁定 Creative Brief。
4. 根据 Brief 生成脚本和逐镜头 Storyboard，并允许用户确认和局部修改。
5. 对确认镜头选择用户素材、AI 图/视频、图片运动、Blender 或库存素材等策略。
6. 生成一条可下载的竖屏 MP4，并能追溯每个镜头的来源、版本、耗时和资源消耗。
7. 内部管理员能通过界面配置模型平台、API Key、能力路由和主备切换。

### 3.2 非目标

- 不训练通用 LLM、视频或 3D 基础模型。
- 不承诺或预测具体播放量、涨粉和转化。
- 不在 P0 做多人协作、团队审批、计费、套餐或自动发布。
- 不在 P0 支持任意车型的影视级 3D 模型从零自动生产。
- 不把节点图、采样器、任意 Blender Python 或供应商参数暴露给普通用户。
- 不在 P0 同时上线母婴/育儿内容生产；只用一个跨垂直样例验证扩展边界。

## 4. 核心用户旅程

```text
创建项目
  -> 输入想法 / 上传素材
  -> AI 理解账号、受众和目标
  -> AI 搜索并诊断机会
  -> 比较 2-3 个创意方向
  -> 对话修改、合并或采用推荐方向
  -> 锁定 Creative Brief
  -> 生成脚本 + Storyboard
  -> 用户编辑并确认
  -> 低成本预览
  -> 逐镜头生成与局部重试
  -> 合成、质检、下载成片
```

## 5. 功能需求

### FR-01 项目创建与输入

- 一个主输入框接受自然语言，不强制完整表单。
- 可选上传图片和视频，并显示分析进度和可用性。
- 系统保存原始消息，不用后续总结覆盖。
- 提取主体、车型、宣传语、必需镜头、顺序、人物、环境和限制。
- 用户确认事实的优先级高于搜索结果。

### FR-02 账号与内容上下文

- P0 可维护一个轻量 Account Brief：内容方向、目标受众、常用语气、日更频率和不喜欢的表达。
- 项目可覆盖 Account Brief，但不静默反向修改账号默认值。
- 没有账号资料时使用摩托车内容包默认值，不阻塞创建。

### FR-03 搜索与 Evidence Pack

- AI 可生成搜索计划并调用搜索、网页读取和媒体检索工具。
- 每条 Evidence 保存来源 URL、标题、时间、摘录、用途和置信度。
- 区分 `Project Facts`、外部证据和创意假设。
- 搜索失败时可基于通用方法继续，并在 UI 中标注依据范围。

### FR-04 AI 创意顾问

- 在脚本生成前输出 2 至 3 个 Strategy Proposal。
- 每个方案包含受众、目标、Hook、核心承诺、视觉回报、节奏、情绪峰值、结尾、素材需求和资源等级。
- 方案必须说明推荐理由、局限和主要不确定性。
- 用户可采用、追问、重写或合并方案，也可坚持自己的方向。
- 系统保存用户选择原因和方案版本，不用“AI 推荐”阻断用户决策。

### FR-05 Creative Brief 确认

- 选中或合并方案生成结构化 Creative Brief。
- Brief 至少包含平台、受众、目标、内容类型、核心观点、Hook、语气、视觉语言、时长、CTA 和硬约束。
- 用户点击确认后生成不可变版本。
- 修改已确认 Brief 时创建新版本，并使依赖脚本和 Storyboard 标记为需要更新。

### FR-06 脚本和 Storyboard

- 基于已确认 Brief 生成旁白、屏幕文字和 4 至 6 个原子镜头。
- 每个 Shot 显示目的、时长、画面、动作、运镜、声音、素材来源和生成策略。
- 用户能修改文案、调整顺序、删除、替换素材和要求单镜头重写。
- 用户明确给出的镜头顺序默认保留；模型扩展必须可见。
- 用户确认后保存不可变 StoryboardVersion。

### FR-07 媒体路由与预览

- 每个 Shot 独立选择 `user-video`、`image-to-video`、`generated-video`、`image-motion`、`blender-3d`、`stock-video` 或 `avatar`。
- 首期路由理由对用户可理解，例如“使用 3D 以稳定完成整车环绕”。
- 最终生成前展示低成本预览、预计耗时和相对资源等级。
- 单镜头可重试或降级，不从头重做整条视频。

### FR-08 合成、质检与交付

- 合成旁白、字幕、音乐、环境音和镜头。
- 自动检查格式、时长、黑帧/静帧、音轨、响度和字幕安全区。
- 显示项目和镜头进度、失败原因、可重试动作。
- 交付 H.264 MP4 和项目内预览；P0 不自动发布。

### FR-09 垂直内容包

- 平台核心不硬编码摩托车字段或 Blender 必选逻辑。
- 内容包定义输入扩展、Advisor Playbook、Prompt、镜头目录、素材路由、质量规则和示例。
- 摩托车包首期提供产品展示、越野能力、细节审美、对比/评测和骑行故事等内容类型。
- 用一个母婴/育儿 Advisor 样例验证可以替换诊断与建议，不要求生成最终视频。

### FR-10 模型管理后台

- 内部管理员通过界面管理 Provider、API Key、物理模型和业务能力路由。
- API Key 只允许写入、测试、轮换和撤销，任何界面与接口均不回显明文。
- 路由修改先保存为 Draft，通过探针后发布为不可变版本，并支持回滚。
- 切换只影响新请求，执行中的 Run 使用启动时路由快照。
- 支持查看调用模型、Token、耗时、费用、错误、重试和 Fallback 链。
- 普通创作者界面不显示底层 Provider、模型名和 Key。

详细交互见[模型管理后台体验规格](model-management-console.md)，调用契约见[模型接入、切换与 API Key 规格](model-provider-routing.md)。

## 6. 摩托车 Advisor Playbook v0

| 内容类型 | 主要目标 | 优先 Hook | 视觉证明 | 不应默认补写 |
| --- | --- | --- | --- | --- |
| 车型展示 | 形成车型记忆 | 最强姿态或标志细节 | 360 环绕、灯组、轮组、漆面 | 未核实配置和性能数字 |
| 越野能力 | 建立力量与通过性感受 | 沙尘、涉水或抬头结果 | 路面反馈、悬挂动作、仪表反应 | “最强”等宣传语不能当客观结论 |
| 评测/对比 | 帮助选择 | 明确问题或差异 | 同条件细节、参数来源、实拍 | 没有依据的胜负结论 |
| 知识科普 | 建立专业感 | 常见误区或具体问题 | 部件特写、图层说明、示范 | 模糊来源的事实参数 |
| 骑行故事 | 建立情绪连接 | 结果、冲突或目的地 | 人车关系、路线变化、高潮镜头 | 用户未提供的真实经历 |

## 7. P0 默认输出规格

以下为待评审默认值，不代表已确认：

- 平台：抖音优先，仅下载。
- 画面：`9:16`，`1080 x 1920`，30fps。
- 时长：20 至 30 秒，4 至 6 个原子镜头。
- 语言：简体中文。
- 输出：H.264 MP4、AAC 音频、硬字幕。
- 风格：默认电影感、快节奏，但由 Advisor 根据内容类型调整。
- P0 用户：本机单用户，不做登录和计费。

## 8. 成功指标

### 8.1 P0 可验收指标

- 两个摩托车样例均产生至少 2 个实质不同的策略方案。
- 评审者能在不编辑 JSON 的情况下完成选择、合并、Brief 确认和 Storyboard 确认。
- 100% 用户确认 Project Facts 在检索和改稿后保持不被静默覆盖。
- 单镜头修改不会触发无关镜头重新生成。
- 每个生成 Artifact 可追溯到 Brief、Storyboard、Prompt、Provider 和输入资产版本。
- 最终文件满足输出规格且通过自动媒体检查。
- 模型平台与主备路由可通过管理界面切换，无需改代码、配置文件或重启业务服务。

### 8.2 MVP 上线后观测指标

- 首次输入到锁定 Brief 的中位耗时。
- 方案直接采用率、合并率和放弃率。
- Brief 确认前平均对话轮数。
- Storyboard 一次确认率和单镜头修改率。
- 成片成功率、镜头重试率、平均生成时长和单位视频资源成本。
- 7 日内重复创建项目的用户比例。

指标用于比较产品流程，不把播放量作为 P0 验收门槛。

## 9. 待项目方评审的决策

1. 是否接受第 7 节的 P0 默认输出规格。
2. Creative Brief 和 Storyboard 两次确认是否符合期望。
3. P0 是否先做本机单用户版本，再部署外部测试环境。
4. P0 首个真实 LLM、搜索和视频 Provider 的可用账号/API 凭证。
5. 真实车型保真标准：整体可识别，还是关键部件及年款也必须准确。
6. 免费测试阶段预计用户数和每人每天视频数，用于得到首个成本上限。
