# ADR-0003：混合生成与组装路线

- 状态：已接受
- 日期：2026-09-05
- 替代：ADR-0001

## 背景

平台的主要能力是通过 AI 与用户交互，从文字、图片和视频等输入生成脚本、素材并组装成社交媒体视频。用户通常只提供创意思路和文字，但也可能提供照片、多角度图片或视频。Blender 3D 是摩托车方向的重要画面能力，但不能成为所有内容方向和所有镜头的前置条件。

## 决策

以 Storyboard 和 Shot Manifest 为统一契约，每个镜头独立选择最合适的 `renderStrategy`：

- `user-video`：裁剪、调色和重构用户视频。
- `image-to-video`：用用户图片或 AI 参考图生成动态镜头。
- `generated-video`：直接通过文本/参考图生成视频。
- `image-motion`：对静态图片进行景深、推拉摇移和图层动画。
- `blender-3d`：通过 Blender 场景、模型和受控参数渲染。
- `stock-video`：检索并重组库存素材。
- `avatar`：数字人口播或角色镜头。

脚本与 Storyboard 先供用户确认，确认后才执行高成本策略。所有镜头最终转换为统一的视频、音频和字幕时间线，由合成 Worker 输出成片。

## 车型一致性

摩托车内容包建立 Reference Pack，包括车型名称、年款描述、用户图片、AI 参考图、颜色、主要外观特征和负面约束。后续镜头尽量共享 Reference Pack、随机种子和生成参数。

只有文字时，系统生成 Reference Pack 并让用户确认。该方式可以提高一致性，但不保证机械结构和年款细节完全准确。用户图片越完整，图生视频路线的外观约束越强；存在高质量 3D 资产时，Blender 路线适合整车环绕和结构特写。

## 理由

- 符合平台“生成、组装、处理”的通用定位。
- 用户有素材时能直接复用，降低成本并提高真实性。
- 没有 3D 资产时仍可完成视频，不阻塞车型覆盖范围。
- Blender 能集中用于最能体现价值的镜头。
- 母婴、育儿等内容包可以复用同一工作流而不依赖车辆资产。

## 代价

- 不同生成策略的画面风格和车型细节可能不一致。
- 需要统一分辨率、帧率、色彩、时长和音频的合成规范。
- 需要镜头路由器、失败降级和跨供应商成本记录。
- Reference Pack 和用户确认只能降低错误概率，不能等同于工程级车型还原。

## 验证条件

P0 使用同一车型脚本生成三个版本：以 AI 视频为主、以 Blender 为主、AI 与用户素材混合。共同评审质量后，记录每条路线的生成时间、人工步骤、失败率和成本，再决定默认镜头路由。
