# ADR-0002：平台核心与垂直内容包

- 状态：待确认
- 日期：2026-09-05

## 背景

首期聚焦摩托车 3D 视频，但已明确需要扩展母婴、育儿等内容。不同领域的输入、资产、生成方式、事实要求和安全检查不同。摩托车依赖真实车型目录与 Blender；母婴/育儿可能依赖实拍、图像动画、数字人或生成视频，并涉及更严格的内容审核。

## 决策

系统分为稳定的平台核心和版本化垂直内容包。

平台核心管理项目、创意简报、脚本、Storyboard、Shot、审批、运行、产物、队列、成本、质检和导出。垂直内容包提供输入 Schema、创意规则、领域资产、镜头类型、渲染策略、真实性检查、审核策略和 UI 预设。

Shot 通过 `renderStrategy` 选择 Blender 3D、生成视频、图片动画、库存视频或数字人等 Worker。平台核心不依赖任何具体策略。

## 理由

- 可以先把摩托车体验做深，同时保留增加其他方向的清晰边界。
- 各领域可以独立迭代提示词、资产、模型和审核规则。
- 通用项目、版本、审批、队列、成本和成片能力只建设一次。
- 避免为抽象而抽象：只有已经被两个内容包验证的共同行为才上移到平台核心。

## 代价

- 内容包需要明确版本、接口和契约。
- 首期开发要守住边界，不能把车辆字段直接写进通用 Project 或 Shot。
- 第二内容包落地前，部分扩展设计仍只是待验证假设。

## 验证条件

摩托车 P1 完成后，用一个最小的母婴或育儿内容包创建项目、生成脚本与 Storyboard、执行非 Blender 镜头、完成审批与导出。如果不修改核心状态机和核心数据表即可完成，说明边界基本成立。
